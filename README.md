# Satisfactory World Planner

A whole-map production planner for Satisfactory 1.0. You decide what the world
should produce; it derives every recipe, machine, and raw-resource draw beneath
that, checks the total against real node data, and places complexes on the map.

Built for planning an entire playthrough before building anything in-game.

## Run it

Easiest: download the built `index.html` from the Releases or Pages deployment
and double-click it. It is fully self-contained - no install, works offline.

To work on the source:

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # single self-contained dist/index.html
```

Pushing to `main` builds and publishes to GitHub Pages automatically.

## Layout

```
public/data/        data, generated by scripts rather than edited by hand
  recipes.json      284 machine recipes at per-minute rates
  nodes.json        594 resource nodes: [resource, purity, type, x, y, capacity]
  plan.json         the complexes and their production steps
  goals.json        end products being aimed for
  mapbg.json        generated terrain/biome backdrop
  world.json        world bounds, used to georeference the map image
src/lib/model.jsx   the maths: recipes, machines, power, cross-complex graph,
                    goal solver, placement scoring
src/lib/storage.js  persistence - localStorage today, swap for a server later
src/components/     one file per tab
src/styles.css      all styling
```

Coordinates are in units of 10 m, matching the extracted game data.

## Conventions

- Resource capacities assume Mk.3 miners at 250% overclock.
- Water is unlimited: extractors work on any lake, river or ocean, so it never
  constrains placement.
- A step's **target** is the rate you want of the recipe's *primary* product.
  `exact` trims the clock so output lands exactly on target; `full` runs every
  machine at the set clock and overshoots; `max` computes the target from nodes
  you assign.
- Node allocation is whole-node: claim the whole miner, sink the excess, rather
  than trickle-balancing inputs.

## Making it multiplayer

`src/lib/storage.js` is the only file that touches persistence. Replace its four
methods with calls to a small API and every client shares one plan. GitHub Pages
is static-only, so shared build progress needs a server (an Unraid container
serving the same static files plus a tiny JSON API is enough).
